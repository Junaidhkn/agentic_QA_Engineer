# Benchmarks

Evaluation corpus and harness for the agentic workflows (docs/architecture/evaluation.md).

- `reference-apps/` — small apps in the supported stacks with `labels.json`: expected routes and
  pages (route-recall ground truth), how to run the app, and seeded defects (`DEFECTS=…`) with
  their mechanism and the files a correct fix touches (diagnosis and repair benchmarks).
- `harness/run_evals.py` — runs discovery on every app and, where the app can be started,
  dry-runs the generated tests 3× with k6. Writes `benchmarks/out/report.json` and a Markdown
  summary, and exits non-zero when a gate fails.

```bash
cd services/control-plane
uv run python ../../benchmarks/harness/run_evals.py            # deterministic baseline (no API key)
RE_LLM_PROVIDER=anthropic RE_ANTHROPIC_API_KEY=… \
  uv run python ../../benchmarks/harness/run_evals.py --llm    # with the model step
```

`--sandbox` also builds and starts every app in a process sandbox (set `RA_SANDBOX_POSTGRES_URL`
for apps that need a database) to measure sandbox build success.

Gates (evaluation §4): route recall ≥ 95%, generated-test validity ≥ 85%, sandbox build
success ≥ 80% (plan.md Phase 6).

## Diagnosis and repair benchmarks

Both run the seeded defects end to end against the real control plane and a process-sandbox
runner (`services/control-plane/tests/benchmark`, opt-in with `RE_RUN_BENCHMARK=1`; CI jobs
`diagnosis` and `repair` in `.github/workflows/evals.yml`). Uploaded sources exclude
`labels.json`, the defect README and `repairs/` so the agents never see the answers.

- **Diagnosis** — detection, top-1/top-3 precision against `labels.json`, citation validity,
  calibration. Writes `benchmarks/out/diagnosis.{json,md}`.
- **Repair** — `reference-apps/<app>/repairs/` holds, per defect, a regression test, an oracle fix
  and a decoy fix (plausible but wrong, each aimed at one verification gate), generated by
  `harness/make_repair_fixtures.py`. The oracle is applied by a scripted stand-in for the model
  that drives the real repair graph and tools; it must end *verified*. The decoy is handed
  straight to verification and must *not* be verified. With `RE_LLM_PROVIDER=anthropic` the
  agent's own verified rate is measured instead. Writes `benchmarks/out/repair.{json,md}`.

Gates: top-3 ≥ 60% (diagnosis); oracle pass ≥ 90%, false-verified < 5%, agent verified ≥ 40%
with a real model (repair).

## Platform load test (NFR-4)

`harness/platform_load.py` replays the reference platform load against a deployed API:
`--load-concurrency` load runs kept active (one *lane* per verified target, default 25) plus
Poisson functional arrivals (`--functional-per-hour`, default 100) for `--minutes`, then
reports job start (`started_at − queued_at`, queued → first container running) by kind.
Pass: p95 < 30 s, no run errored for platform reasons, no submission refused.

```bash
uv run python benchmarks/harness/platform_load.py --api-url https://api.staging.example \
  --lanes lanes.json --minutes 60 --functional-per-hour 100
```

`lanes.json` lists `{api_key, project_id, target_id, load_profile_id}` per lane; give each
lane its own API key (run creation is rate-limited per key) and make sure every target had
its first, approved load run. Reports go to `benchmarks/out/platform-load.{json,md}`.

CI runs a scaled version on every change (`tests/integration/test_phase10_platform_load.py`:
3 lanes, 4 runners, real k6, one minute).
